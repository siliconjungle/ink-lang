# Path-local indexed tables: paired measurements

The new sequence-tree implementations live in Ink knowledge. They preserve exact row order and duplicate behaviour, filtered wrapping `u64` sum/count, failed changes, rollback and portable logical state. The compiler adds general constructor case checking, compact-observer proof checking, shared-owner forwarding and bounded typed continuations. The Wasm host also removes an unnecessary response-byte copy and exact-JSON parser allocations. No indexed-table algorithm is recognised by the compiler.

These are exploratory paired measurements on a shared Apple M2 desktop running macOS 26.5.2 and Rust 1.96.0. Every measured script compares complete JSON replies, events and acknowledgements against the independent reference evaluator and checks exact final portable snapshots outside the timed call loop. Native executables use release optimisation, thin LTO and one codegen unit. Handwritten Rust uses the same action/reply/event contract; both a scanner and an incrementally maintained aggregate are recorded. Ordinary compiled Ink is a separate baseline from the reference evaluator. The oracle is sampled once per identical script, with that reuse explicit in schema 4.

Median milliseconds per **1,000 complete calls at 4,000 rows**, three samples per cell:

| Implementation / workload | Indexed Ink | Ordinary compiled Ink | Handwritten incremental Rust |
|---|---:|---:|---:|
| Sum, 100% reads | 0.429 | 21.498 | 0.325 |
| Sum, 90% reads | 1.547 | 26.575 | 0.472 |
| Sum, 50% reads | 6.329 | 19.093 | 1.021 |
| Sum, 10% reads | 26.498 | 5.565 | 1.623 |
| Sum, 0% reads | 20.440 | 7.787 | 1.685 |
| Count, 100% reads | 0.401 | 22.557 | 0.286 |
| Count, 90% reads | 2.355 | 71.513 | 0.498 |
| Count, 0% reads | 16.608 | 2.359 | 2.495 |

The useful result is a workload crossover. Cached reads outperform repeated scans, while ordinary compiled source can be cheaper for predominantly writes. Handwritten incremental Rust remains faster in these cells. This does not establish an overall ranking of programming languages. The large variation across adjacent mixes also prevents a precise universal crossover estimate.

The corrected executor also completes **20,000- and 100,000-row** workloads. At 100,000 rows, median time for 100 indexed sum reads is 0.168 ms versus 159.333 ms for ordinary compiled Ink and 0.039 ms for handwritten incremental Rust. For 100 writes the times are 1.580, 0.252 and 0.183 ms respectively. Portable indexed initialization takes 0.907 s and the recorded switch to the count candidate takes 1.188 s. Those are single lifecycle samples, excluded from steady-state timings. They are material costs for short-lived workloads. An earlier single-site continuation experiment overflowed the stack on conditional recursion; the final executor and full large workload pass after extending the general continuation lowering.

Allocation instrumentation runs in a separate executable and its timings are excluded from speed claims. At 4,000 rows, 100 writes request 1,508,017 allocations / 153,112,984 bytes for the flat sum-delta implementation and 8,096 / 3,079,720 bytes for the indexed implementation. Cached indexed reads request 701 allocations / 74,800 bytes for 100 calls. Requested bytes measure allocation traffic, and peak additional live bytes exclude already resident state; neither is a complete process-memory measurement. Continuation storage adds allocation cost, even though it removes the stack limitation. Generic owner-forwarding tests also verify zero allocations and identical shared edges through a helper call.

Both release Wasm guests run the same checked flat sum-delta package. A paired host comparison alternates old/new host ordering over 15 rounds of 10,000 cached reads at 4,000 rows. Median complete-call time falls from 14.133 to 13.369 microseconds for Rust-Wasm and from 15.383 to 14.573 microseconds for C-Wasm: approximately 5–6%. The separate instrumented boundary profile identifies response decoding as a major host cost. Mixed-write measurements are noisier and do not establish a consistent host speedup; guest execution dominates the flat write path. Reserved linear memory is reported separately and is not live allocation. These guest measurements include JSON transport and must not be compared directly with native timings as a backend-only overhead estimate.

`final-compilation-debug.json` separates checking each proof package, literal emission and the Cargo release build. Checking/emission use the debug compiler; the build duration includes dependencies, harness compilation and any shared-machine lock waits. Initialization and portable migration appear under report phases rather than the call samples. Compiler/source/request/generated-code/executable hashes and exact independent component revisions are in `final-provenance.json`.

Database publication stores shared proof roots rather than duplicating large proof views in each candidate. Append publication reuses existing authenticated content references and incrementally refreshes its disposable index. Retrieval still validates object hashes and pinned membership, and selection replays ordinary checking. Canonical snapshots remain authoritative; neither SQLite indexes nor timing observations grant correctness.

Whole-batch observations in the knowledge database bind the source, candidate ID, compiler hash, emission target, exact row/call count, query and read mix. `action:batch_calls` is the measured unit, not an estimate of each individual action. The supplied selection profile describes steady execution only. Missing ordinary initialization, compilation, migration or memory observations do not justify a lifecycle switch or a memory guarantee. The read/write selection receipts record the resulting choice and their exact snapshot/evidence identities. Replay rechecks the chosen package before emission.

Validation includes the independent core suite, 59 planner tests, canonical-store and append-publication tests, falsified compact-observer rejection, 100,000-row typed filtering/codec/release, and the complete standalone representation suite. After the multiple-site continuation extension, filtered deltas and both new sequence candidates pass fresh C/Rust/JavaScript/both-Wasm/both-GPU-host comparisons. Wasm host tests cover exact large integers, malformed/over-deep JSON, safe object keys, memory growth, release on failure, owned snapshots and durable recovery. The release profiles independently compare all replies and snapshots. Recursive tree execution on GPU routes remains host work; no tree GPU-kernel speedup is claimed. Logical proofs do not prove backend machine code or universal logarithmic tree cost, and arbitrary overlapping key ranges can require a full traversal.

Final artifacts are `final-sum.json`, `final-count.json`, `final-large.json`, `final-allocations.json`, `final-compilation-debug.json`, `paired-cached-read-wasm-io.json` and the selection receipts. Other reports preserve intermediate stages: baseline measurements bind merged main b54439f3; subsequent integration includes main 3c5bd626. The original debug Wasm report and earlier single-site/native runs remain historical evidence. Stage labels and their compiler profiles matter.

Reproduce native generation with `INK_BENCH_REQUEST_DIR=build/final-indexed-benchmark-requests INK_BENCH_PLANS=direct,refresh,sum-delta,count-delta,indexed-sum,indexed-count cargo test --test point_delta benchmark_standalone_aggregate_scaling -- --ignored --nocapture`. Populate that request directory from the current filtered-aggregate and indexed-sequence fixtures. The generated benchmark accepts bounded `INK_BENCH_ROWS`, `INK_BENCH_CALLS`, `INK_BENCH_ROUNDS`, `INK_BENCH_READS`, `INK_BENCH_QUERIES` and `INK_BENCH_CANDIDATES`; defaults are documented in its source. Allocation profiling uses its separate `allocation-profile` Cargo feature. `tools/profile_representation_wasm.mjs` accepts generated JavaScript, both release Wasm guests and the shared host, with optional `INK_PROFILE_BASELINE_HOST`, bounded rows/calls/mixes/rounds. Proof views cap at 4,096 entries / 64 MB, individual entries at 16 MB, and new native continuation storage at one million frames / 64 MB.
