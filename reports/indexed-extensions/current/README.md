# Indexed key, insertion and recursive row extensions

The source-bound catalogue adds every admitted ordered key domain, nine ordered
edit-pair families and finite direct/mutual recursive row carriers. Predicates
without a proved summary decomposition retain exact source evaluation. Typed
query and edit discovery needs no new application syntax.

`javascript.json` measures ordinary, indexed and grouped general-row programs at
1,024 rows, 96 calls and five alternating rounds. `write-comparison.json` compares
the same indexed proposal through the previous and updated JavaScript lowerers.
Both scripts assert repeated replies and portable snapshots agree. Raw samples,
module hashes and acquisition compiler identity are retained. This was a shared
8 GB Mac with other work running; these are workload observations, not a universal
speed claim or isolated attribution experiment.

Removing redundant private-node freezing and classifying recursion by actual
self calls improved the four measured indexed write medians. Ordinary storage
still wins those writes and dynamic predicates by substantial margins. Maintained
queries remain cheaper on this fixture. The existing lifecycle selector must
consider the actual workload rather than always choosing indexed or grouped.
Some indexed/grouped operations and cached reads regress relative to their other
physical candidate; grouping eligibility remains a measured decision.

The full benchmark includes restore and checkpoint/GC teardown, but does not price
offline proof checking, compilation, live migration or memory. The four-action
write comparison is a mechanism comparison; its teardown uses the final cached
query cohort, not a dirty write cohort. Those omissions must remain explicit in
any selection profile.
