## Mechanism and trust

Lists of at most 32 elements keep their old representation. Longer closed lists
and frozen table rows share tails in 16-cell definitions. Source-derived literal
bodies use exact dependencies, so unrelated helper sorts do not change constant
identity. Selection checking rebinds the definitions referenced by frozen
premises, including roots no selected action reads. The producer includes those
ordinary definitions in its checked evidence closure; it supplies no new premise.

An action case's `normal` is an authoring hint, never proof authority. If full
normalization exceeds existing computation bounds or produces an untransportable
hint, it retains the exact typed case call. Exhaustive constructor elimination
returns the exact equation checked in every branch, instead of expanding the
complete conclusion again. Later uses still require ordinary conversion. This
adds no axiom, proof variant, primitive, source syntax or approximation permission.
Arithmetic order, capabilities, rollback and checkpoint meanings stay fixed.

## Remaining work and negative controls

Finite model-data specialization reaches 512 values, but a generated 32-step
straight-line action can still hit continuation bounds. Larger neural graphs and
tapes need shared computation and factored equality proofs, not only shared data.
Work/definition/byte budgets remain finite and can still reject larger values.

Repeated exceptional-value bitcasts expose another concrete authoring limit:
a complete 64-value list specializes, while 128/244-value lists reject after the
compact proof attempt and the normalization tactic's depth budget. Exact raw-bit
transport itself passes core tests; equivalent long literal expressions still
need factored producer proofs. `negative-controls` retains these inputs, the
successful 64-value selection and observed statuses. Rejection is conservative,
not permission to change an exceptional value. The supplied parameters are
configured data; this fixture does not fit them or demonstrate convergence.
