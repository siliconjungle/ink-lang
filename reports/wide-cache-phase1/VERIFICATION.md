# Signed application, profile sensitivity and allocations

This experiment executes a real compiled Ink table/change/query program, not a direct call to an isolated arithmetic kernel. It keeps two rows, maintains an exact total, advances commit versions and returns logical observations. The fixed row is `2^bits`; the changing row is drawn from 32 signed values. Profiles differ in whether that changing row is small or near the anchor magnitude. An exponent of 8192 means an anchor with 8193 significant bits. Inputs/state preparation, JSON/decimal observations and final validation are outside timing. Optional queries include exact digest conversion in timing.

The original compiler emits the cloned canonical source. The current compiler emits borrowed canonical and delta-first sources; its generic kernel and semantic bridge are unchanged. Handwritten Rust uses BigInt/BTreeMap, validates before mutation and maintains the total with the same delta-first expression in place. It has no undo journal and can inspect the total directly. All input wrappers clone the typed update argument. These differences are disclosed rather than attributed solely to the surface language.

There are 448 samples: 16 cells × 4 variants × 7 repeats. Each cell has a distinct exponent/profile/query combination. Every sample's final rows, exact signed total, version and consumed digest checksum are compared with an independent Python integer oracle. Separate native ABI checks observe every update in 128-step sequences across both profiles and four exponents: 4,096 comparisons. The audit reproduces those checks, 64 measured native streams, archived hashes and exact emitted source/plans without rebuilding timed binaries. It also reproduces the 37-object database extension with the original unchanged compiler.

Borrowed/canonical runs 1.23× faster than cloned/canonical overall. The delta choice helps the small-changing-row profile by 1.05× overall; at exponent 8192 with no queries it improves from 165.8 to 141.9 ns/update (1.17×). It is about 3% slower on the wide-changing-row profile overall. Ratios near one on a shared host can be noise. This is evidence to retain multiple safe alternatives and profile their cost, not proof that delta-first is universally best. Delta Ink still takes 2.98× handwritten Rust BigInt time overall.

`allocations.json` comes from **separate instrumented builds**, not the timed artifacts. A System allocator wrapper counts allocation/reallocation calls and requested sizes only during 128 updates; setup, observations and queries are excluded. Its complete instrumentation source, commands, source hashes and binary identities are recorded. All 32 cases check exact final state against Python, and executed audit regenerates identical counts. It does not measure retained memory, peak RSS or allocator time. At exponent 8192 on the small profile, cloned averages 3.492 calls/update and 4092 requested bytes/update; borrowed and delta average 2.492 calls/update and 3064 requested bytes/update. Handwritten Rust reuses existing capacity with no allocation calls in that profile. This supplies a concrete remaining runtime cost, not a whole-process memory comparison.

The full 63-test suite (`tests.log`) also checks aborts, events, tentative reads and continued snapshots in the three candidate implementations. This timed two-row application itself has no abort/event workload, concurrent access or durability. C/C++ comparison is in the companion inventory report. The Rust kernel, correspondence, cache/transaction protocol, representation analysis and backend remain trusted; complete formal state-transition/representation proofs and measured automatic adaptation remain unfinished.

Measured scripts/runtime inputs are in `sources/`; final audit, allocation tool and tests are separately in `verification-sources/`, under `verification.json` hashes. Only a table label and unused Python import changed after timing. Samples and runtime sources are unchanged. Original/current compiler identities and raw native artifacts are pinned in metadata; executed audit rejects changed binaries. Reproduction requires the recorded original compiler at `build/cache-lowering-original/lang`, recoverable from the prior commit/report source identities.

python3 bench/wide-cache.py
python3 tools/cache_allocations.py
