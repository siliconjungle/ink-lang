# Boundary allocation experiment

The generic typed builder experiment removes per-operation closures and expected-node objects. The JSON reduction consumer also removes each temporary member result object, keeping duplicate-key sets in a nested invocation-local stack. These changes preserve values and exact portable/compact bytes on all benchmark fixtures. Independent conformance checks cover recursive values, exact numeric tokens, malformed numeric values, nested duplicates, repeated renders after failure, ownership and resource bounds. The full JavaScript package suite passed for the first builder change.

Processes 293 and 294 are retained but rejected as selection evidence. Their same-source controls have large inconsistent shifts, including the unchanged prepared-output lane. At 512 fields, Frontier's complete text/edit/text median is 661.396 and 201.194 microseconds respectively, against about 100 microseconds in the earlier cohort. Concurrent compiler, tests, planning, archive and indexing work was observed on the shared host. No speedup or default profitability claim follows from these runs; do not aggregate them into a winning result.

Exact modules, selected layout, runner, conformance checks and host-load observation are in `artifacts/boundary-allocation-293-294`. The runner binds actual installed Frontier JavaScript bytes as well as Git revisions. Modules contain experimental literal support substitutions into the frozen prior emitter output; they are not claimed to be generated by the current compiler. The further scalar-path argument-array change is not measured in this epoch.
