# Compact checked-reader specialisation

Compact values have no per-node byte-length frames. An explicit compact checked reader retains depth with a counter and bounds all scalar/count/text reads against the complete buffer. Portable reading keeps its original frame-end stack. Node/depth checks, canonical counts, Bool/sum tags, Unicode, schema/format headers, allocation bounds and full byte consumption remain active. Malformed inputs still replay the independent scanner for established diagnostics.

Three fresh processes per variant, fifteen rotated rounds, a512-member numeric JSON document, identical admitted source/layouts and complete output-byte consumption. Processes355–357 test an initial combined-class counter and are mixed; that version is not retained. Processes358–360 use a separate compact reader: complete fused decode/re-encode ratios are **0.890 /0.889 /0.860**, about11–14% less time in all three. The ordinary compact decoder is an unchanged control, with ratios0.967 /0.995 /0.937. Shared host; no confidence bounds or Frontier win follows from this Ink-versus-Ink diagnostic.

The full ABI suite passes, including literal nested list/record/Bool/string readers versus the independent decoder, every prefix truncation, byte corruption, trailing bytes, Unicode and reduced node/depth/byte limits. Full emitted JavaScript conformance is checked separately before publication. Initial measurements use exact ABI support substitutions into a frozen generated module, not a new compiler build. Artifacts retain both candidates, baseline, runner, raw timings and source. Generic emitter readers and database-selected fused boundary strategies remain separate from this fixed validation mechanism.

Fresh compiler emission replays the same admitted plan and embeds byte-for-byte identical ABI support. Its complete module differs from the measured frozen module because newer JavaScript main adds word primitives, ordered-key machinery and private interface guarantees. The full JavaScript suite passes on that newer emitter with this reader. `fresh-emission.json` records both hashes; initial timings are not relabelled as fresh-emission measurements.
