# Compiled learned advice over whole checked structures

The optional compiled source goal receives a complete, shallow node-and-edge
representation of the checked implementation state and captured typed context.
The source example trains a four-feature linear policy with complete Adam state.
This supplies an exploration mechanism; it is not a pretrained model or a claim
of learned generalization, faster compilation, runtime speed or Handwired parity.

## Local validation

- Two root integration tests passed with mandatory independent reference,
  native, JavaScript and Wasm comparisons and separate actual native GPU controls.
  Training, invalid-update rollback, exact restoration and raw values are covered.
- Under the same three actual kernel proof attempts, the initial source policy
  misses the final simplified program; the trained policy reaches it. All edges
  carry universally checked U32 algebraic equations. Labels are deliberately
  synthetic authored structure scores, not measured hardware cost.
- The actual published-candidate producer discovers the checked alternatives from
  a private database. The public CLI still selects the unchanged baseline without
  comparable lifecycle evidence, despite the model's preferences.
- An invalid proof never acquires a goal priority. Nonfinite predictions, stale
  replies, timeouts and input overflow disable optional advice without restarting
  it. The pending frontier reverts to structural ordering. Failed advice is not
  cached. Captured artifact tampering rejects export.
- Exact u64 tokens above 2^53 survive state/context/frequency transport. Wire
  contexts distinguish +0, -0 and a raw NaN payload. An actual Node 22.22.1 worker
  additionally passed the exact-word smoke test; the main run used Node 25.3.0.
- Thirty-five planner tests passed, including independent deep-document
  reconstruction, complete cache binding and fallback frontier ordering.
- The broader `llvm_learning_and_incremental_knowledge_remain_checked` hardening
  test passed. Its nested knowledge/planner tests remain separate from the new
  end-to-end mechanism checks.

`search.json` retains detailed search/worker/cache receipts. `graph.json` and
`source.core.json` retain the real proof graph; `selected.plan.json` replays the
discovered final program. `policy.core.json`, `policy.mjs` and `after.json` retain
the exact source policy and learned context. `training.json` records training and
snapshot checks. The two `*-parity-*` groups retain complete inputs, independent
expected outcomes/snapshots and actual GPU-host receipts. Goal execution and
binary64 values on GPU hosts use CPU fallback; the F32 controls actually dispatch.

The full frozen default corpus is being evaluated separately with advice disabled.
Its final regression/funnel report will be retained after completion. It does not
establish learned-policy quality. Initial cases overlapped the broader hardening
run; no comparative performance claim will be made from these timings.

## Scope and trust

Knowledge and planner exact independent main revisions are in `packages.json`.
No core or lowering semantics changed. Local builds preserved the user's existing
`core/src/syntax/query.rs` edit (diff SHA256
750cc8098faaad5bd8278f93760af008129ce3c136a79471334c7f604aa564ab), which is excluded
from this publication. The standalone core pin is unchanged.

The goal steers the compiled frontier. Recipe dispatch, inner semantic search,
measurement shortlisting and final evidence-based selection retain their existing
policies. Training happens through explicit source actions; a compilation keeps
its captured model. General in-search fitting and broader learned optimization
remain work. Source/backend translation, adapters and runtime remain trusted
implementation code; these checks do not prove the whole compiler.
