# Numerical values across action boundaries

The existing `i32`, `f32` and `Vec2`/`Vec3`/`Vec4` types now work in action
arguments/results, table values, keeps, events, nested records, lists, options
and results. The source `Type` definition is unchanged. C, Rust, JavaScript and
both Wasm paths share this domain; WebGPU/wgpu uses the host for transactions
and can dispatch eligible pure numerical functions from the same module.

[The runnable fixture](../examples/stateful-numerics.ink) exercises numerical
storage and a pure integer GPU map. For example:

```ink
module readings;
enum Error { Missing, }
record Reading { position:Vec2<f32>, count:i32, }
state Rows:Table<i32,Reading> = Table.empty();
event changed:Reading;
query increment(x:i32)->i32 { return x+1; }
change put(key:i32,row:Reading)->Result<Unit,Error>
  writes(Rows) emits(changed) {
  if Rows.contains(key) { Rows.replace(key,row); }
  else { Rows.insert(key,row); }
  emit changed(row);
  return Ok(());
}
```

## Fixed semantics

`i32` arithmetic and negation wrap at 32 bits; comparisons and table-key order
are signed. `Int(i32)` is exact. `checked_add`, `checked_sub` and `checked_mul`
return an overflow result instead of wrapping. The inferred intermediate error
is `ArithmeticError.Overflow`; public source signatures cannot explicitly name
that builtin type, so map it into an application error as the fixture does.

CPU `f32` addition, subtraction and multiplication round each operation to
binary32 in source order. Scalar comparisons use IEEE semantics: positive and
negative zero compare equal, and NaN compares unequal to itself. Negation flips
the sign bit. Stored-data equality for records, lists, vectors, options and
results compares the raw bits of contained floats. Consequently two identical
stored NaN payloads compare equal as data, while records containing different
zero signs or NaN payloads compare unequal. Pure-source aggregate equality
remains rejected by the pure checker.

JSON accepts finite numbers or a single-field `{ "F32Bits": bits }` object.
Finite numbers round to binary32; values that overflow require the raw-bit form.
Outputs use finite numbers and the raw-bit form for infinities/NaNs. Stored
payloads, pass-through helpers, sign-bit negation and checkpoints preserve all
32 bits, including signaling NaN payloads. Arithmetic NaN payloads can differ
between CPU engines and are not a portable bitwise promise.

GPU floats retain the portable WGSL contract, which permits different rounding,
fusion and subnormal treatment. This change does not claim CPU/GPU bitwise float
parity or introduce floating-point rewrite authority.

Vectors have two through four components of `u32`, `i32` or `f32`. Constructors
and component access work directly in actions; other pure computation forms,
including expression-level lets and bounded repeat, remain available through
pure helpers. Float, vector and record table keys remain rejected. Recursive
record values work where already admitted, but portable recursive state schemas
remain unsupported.

## Binding and storage

Numerical action domains use the explicit `ink-typed-actions-v2` marker. The
elaborator selects it from actual action/keep nodes and signatures, state roots,
events and recursively reached record types. An unrelated unused numerical
pure helper does not change an old action domain to V2. Replay reconstructs the
exact checked representation and rejects an incorrect semantics marker. A golden
artifact generated by the pre-extension core checks old-domain V1 bytes unchanged;
this is not a compatibility guarantee for arbitrary historical research formats.

The portable snapshot container remains version 1: signed integers occupy four
little-endian two's-complement bytes, floats occupy four raw-bit bytes, and fixed
vectors contain exactly their declared components without a length prefix.
Existing program/schema identities bind the types. No schema migration is added.

The general action-value carrier reuses its U32 constructor for signed integer
and float bits, and its List constructor for fixed vectors. The bound source type
distinguishes interpretations; width, element type and arity are checked, and
canonical replay rejects alternate images. Carrier definitions and proof rules
are unchanged. The independent database producer agrees with actual numerical
action arguments, results and events.

## Validation and limits

`tests/numerical_state.rs` compares 101 requests, replies and exact snapshots on
C, Rust, JavaScript, C/Wasm and Rust/Wasm, with restore after every action. It
covers signed limits, raw NaNs, zeros, subnormals, float arithmetic, vector
storage, signed key order, rollback and events. Its mixed wgpu host also dispatches
one signed integer kernel. Malformed ingress fails before state/outbox changes.
`tests/action_values.rs` and isolated core tests exercise independent encoding and
adversarial numerical carriers. CI retains the reproduction source and requests.

These are conformance and data-binding checks. Numerical whole-action logical
projection still fails closed; no numerical replacement proof or native emission
correctness theorem is implied. Physical representation admission remains open.
