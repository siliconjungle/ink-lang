# Independently checked mathematical units

`proof_units::Checker` admits first-order registry declarations one at a time. A new unit passes the existing canonical identity, interface, direct-import, totality, typing and theorem checks. Only the opaque logic entry survives: theorem proof bodies are not retained. A content hash locates an existing witness; it cannot construct one. The checker is not serializable, duplicate admissions reject, and a fresh process must replay all units.

A `proof_units::Scope` names the exact reachable unit closure and pinned snapshot membership. Repeated membership witnesses share a transport dictionary. Missing, extra or unadmitted units, foreign snapshots, bad witness indices and unreferenced witnesses reject. All unit IDs are private to the checker instance. Only selected imports enter the scope; unrelated cached entries cannot become premises. The finite session allowance is 16,384 units and 32 MiB of original canonical declaration bytes. It bounds admission provenance rather than claiming a complete RSS bound.

`planning::check_with_units` supports `maintained_units` steps. The maintained checker re-derives source definitions and fixed fold meanings from the complete checked source and replays every source-specific factorisation, group and mutation equation using the scoped context. Snapshot membership and cached conclusions do not authorize an unchecked source replacement. Ordinary `planning::check` rejects unit steps without an admitted session. Existing complete-plan semantics and old packets remain unchanged.

The sealed definition/maintained witnesses produced by the unit path retain executable definitions, source-bound view obligations and the unit closure, rather than old theorem bodies. Their projected internal bundle is not a portable unchecked proof library. The portable plan carries the unit scope; the host must carry the complete unit data for a fresh checker. Lowerings continue to consume ordinary opaque checked plans, and must explicitly support selected storage capabilities. This is not a compiler or machine-code correctness proof, and does not broaden the admitted mathematical domain beyond first-order registry entries.

Ink OS supplies bounded compressed unit transport and an evictable compiler session. Storage, compression and cached producer metadata grant no proof authority. On eviction or restart the complete dependency closure is replayed before execution can be admitted.
