# Source domains for automatic selection probes

Automatic typed probes used to abort acquisition when one proposed input violated
an ingress precondition. They also assigned synthetic usage to generated contract
checks and duplicate implementation bodies. This prevented the matched browser
suite from measuring alternatives.

Knowledge now authors entry usage from checked contract roles, plus bounded seed
cases from its policy. The planner executes the original checked ingress guards
before reference bodies and filters only false proposals. Every requested phase
must retain inputs and its original lifecycle weight. Supplied workloads/holdouts,
guard errors, ordinary execution failures, timeouts and Result error values keep
their original behavior. A phase with no discovered valid input refuses acquisition.
There is no guard interpreter, function-name matcher or new proof authority.

The acquisition-local cache binds complete lossless argument packets and function
names within one captured source. It reuses successful reference values and false
guard results across transfer boundaries. Floats, signed zero and exact words use
the existing measurement transport. Source changes refuse the result. Recorded
observations bind the actual retained cohort separately from proposed inputs.
Runtime ingress checks and fixed backend execution remain unchanged.

`validation.json` records the pinned baseline, candidate independent revisions,
local checks, exact original 12-workload acquisition and frozen 10-program corpus funnel.
The full runs and initial failure logs remain in the local artifact archive
`outputs/llvm-ink-audit/probe-contracts`. They are not runtime performance claims.

Reproduce the focused checks with the distribution and its exact package pins:

```
PYTHONPATH=knowledge:planner python3 -m unittest discover -s knowledge/tests -p test_selection_probes.py
PYTHONPATH=knowledge:planner python3 -m unittest discover -s planner/tests -p test_probe_validation.py
PYTHONPATH=knowledge:planner python3 planner/tests/automatic_contract_measurement_integration.py /absolute/path/to/ink
cargo test --test automatic_compilation
```

The new mandatory test runs actual JavaScript and native Rust acquisition, preserves
explicit input errors, rejects empty required phases before publication and rejects
a forged source guard. The existing automatic test covers Rust/JS/Wasm values,
float order, errors and portable snapshots. The warm-cache integration also replays
a complete selected chain, rejects a corrupted proof and checks 24 held-out inputs.

The prior browser input now retains 333 of 360 proposals across all 36 phases and measures
eight checked candidates. No candidate clears the 5% lifecycle gain gate, so baseline
is retained. Matrix proposals currently find width 1 only; this does not model larger
matrix regimes. Arbitrary preconditions may remain uninhabited by bounded proposals.

Both corpus epochs compile 10/10 programs and reuse seven laws. Observed selections
rise 4 to 5 and admitted laws 44 to 45, but time-bounded searches and contended measurements
prevent causal performance/generalisation attribution. The extra index-membership
selection has the same typed input fingerprints and 30 admitted states. Whole-epoch
wall time is recorded, including private knowledge copies; do not infer a compiler
speedup from different planning medians. No runtime adaptive strategy was added.
