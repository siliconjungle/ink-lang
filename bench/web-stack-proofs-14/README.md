# Reusable web proofs, round14

This suite uses fourteen independently compiled task bundles: six collection recipes, six lookup/cardinality recipes, and two vector anchors using existing laws. Discovery recipes and held-out callback instantiations are frozen before timing; held-out does not mean an external corpus. Only the twelve scalar recipes require a fresh law beyond the prior998 catalogue. Both catalogues use the same general planner policy, including its corrected first-result/cardinality cost; the experimental callback matcher was excluded.

Collection calibration is x*3+k, with independent cutoff seed. Ordered checksums use right fold x+acc*k; ordinary totals use wrapping sums. Held-out recipes vary mapper/predicate/reducer family. Lookup uses literal index0 and pure total callbacks that preserve their fallback under a checked compile-time equation; no runtime guard is added. Discovery clamps up to seed before scaling; held-out clamps down to k before subtracting seed. Concat receives an independent second list. Cardinality returns u64 through two u32 ABI lanes, including native high bits.

Original JavaScript/Rust controls preserve eager list stages and exact wrapping operation associations. Expert JavaScript/Rust controls are already fused/skipping: one pass for sums/folds; first-element-only lookup; direct length for self-zip count. Rust uses its normal release optimizer; original materialized Vec stages may be optimized naturally. Expert vector output is reused, and expert JavaScript returns typed scratch views consumed before reuse. Original JavaScript filter and concat allocate one result without unnecessary preliminary copies. No expert algorithm is weakened or retuned after results.

Captured variants include one snapshot of each used list, Wasm copies, output conversion, async boundary and checksum consumption. Borrowed direct JavaScript variants omit snapshots for both Ink and expert, but retain the identical async/checksum driver; they are reported separately. Native resident-input kernels are a separate experiment using identical fixtures and Rust source, including output consumption and generated-C arena reset. Native and web durations are not interchangeable.

Vector anchors use actual schema2 GPU counter evidence, including transfers/readback. Saved schema1 scalar bundles have benchmark-only counter instrumentation, identically applied to all three variants: actual upload writes, compute dispatch invocations and four-byte scalar readback are counted. Original/instrumented device and host hashes are archived; production code/shaders are unchanged. Eligible original scalar sums can execute GPU while selected ordered folds may fall back; such eligibility changes cannot become same-GPU speedups. GPU eligibility, fresh proof applicability and measured profitability are distinct; no GPU acceleration is promised.

Independent Python expectations use mathematical mapper recipes, ordinary sums and forward weighted polynomials for right-fold recurrences; eager source stages independently corroborate outputs. Correctness fixtures include empty lists, independent nonempty tails, singleton/extreme words, zero and unit factors. Timed profiles include three sizes and small/full word distributions, with task-specific cutoffs chosen in advance. Outputs for head/count can intentionally be constant at fixed shapes; cost reduction is consumer work skipping, not hidden artificial repeats.

Startup/module/shader setup and first validation calls are separate from warm timings. All shuffled paired rounds, warmups, calibration, checksums, fallback reasons and exported Wasm memory highwater are retained. Host/GPU memory is not inferred. Individual bootstrap intervals are exploratory and unadjusted for multiple comparisons; all adverse results remain. This suite does not establish broad language superiority or floating-point numerical accuracy.
