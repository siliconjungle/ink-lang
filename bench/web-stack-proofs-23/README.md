# Work-skipping web consumers, batch23

Twelve exact source recipes instantiate partition-count, first-accepted, mapped-first-accepted, unused left/right prefix-scan projections and first-prefix lookup. All signatures naturally declare only `(xs,seed,k)`; the common Rust adapter's empty `ys` slot is never captured. Partition counts return U64 with two Wasm result lanes and a genuine direct native U64 scalar. Other scalars return U32; four vector recipes preserve the original input length.

Original controls retain eager filter/map, prefix-scan/zip and full-prefix construction before lookup. Strong handwritten controls already erase all irrelevant work: count length directly, scan forward until the first accepted word and then stop, map original elements without prefix state, or read only the first word. The selected lookup fold still traverses the entire input and the mapped-first fold evaluates its mapper for every accepted word, in reverse fold order; stronger expert early exit computes only the first accepted mapper and can win even when selected Ink improves over its prior program. Rust scalar algorithms are shared between native and Wasm; native uses their direct scalar result rather than Wasm output stores. Vector experts may reuse their output scratch.

There are228 complete frames and120 timed cells. Each recipe gets nine correctness edges: empty/singleton/extrema, zero factor/seed, equal parameters, all-below/all-above and prefix-overflow data. All four lookup recipes additionally use first/interior/absent locations at every size32/4096/65536 and small/full distribution. These locations are created by remapping only earlier words into the rejected predicate domain and setting the designated accepted word; the absent case remaps all words. Later words remain unchanged. Before/after donor word hashes record every transformation. Other recipes use immutable donor words unchanged. Same seed/k per distribution across all sizes: small512/768, full0x9e3779b9/0xc0000001. This is a synthetic location corpus, not an external application corpus.

The independent Python oracle expresses cardinality, forward first matching and scan-state erasure directly. A separate original-stage evaluator builds all source lists and corroborates every complete result. Before timing, staged and strong JS/Rust and compiled Ink results are compared in full and input nonmutation checked. Measured calls consume complete scalar/vector modular checksums rather than comparing every output to goldens on every iteration.

Captured JS, Wasm copies/transport, native snapshot and actual GPU upload/dispatch/readback have complete-call scopes. Borrowed JS and native resident scopes remain separate. Every declared input stays captured even when the selected algorithm skips all word work. GPU fallback is validated but not timed as GPU; shader eligibility and exact counter evidence decide actual GPU coverage. No handwritten WGSL expert is included. Nine shuffled rounds, two journaled warmups and15ms calibration target use seed20261101, fixed before measurements.

Pure-total finite wrapping semantics allow the callback schedule changes. Source scan supports integer types only; no F32 scan source claim is made. Static proofs, compiler applicability and measured profitability are separate. A result over prior Ink is not evidence that Ink beats expert JavaScript/Rust generally.
