# Scoped branch cardinality in search prices

V8's branch-local facts motivate scoped price analysis. The database enables
maximum-arm lazy choice work and declares the zero-extent branches of count
equality/inequality. The planner prices the condition once, preserves receiver
and initializer work, and shifts local extent terms through lexical binders.
Unrelated receivers and other arms retain their own estimates; a 64-hypothesis
bound retains ordinary estimates on exhaustion. This supplies no checker premise.
No equality checker, emitted execution rule or profitability threshold changes.
Schema2 component models retain their independent analysis.

For the original nested-fold mechanism, old current-main prices were 2602 for
the source and 2916 for the guarded target. The new target price is 314. A
matched before/after search control leaves all three callback forms unchanged
under old branch pricing; the new default semantic search admits and selects
fold, map and filter hoists with ordinary proof replay. These are deliberately
constructed controls, not measurements of opportunity frequency in applications.
The full recipe search also retains baseline without comparable cost evidence;
its bounded frontier coverage and limits are recorded separately.

The official native adapter measures complete generated JSON calls, consumes
every output, checks against independently interpreted source values and checks
unchanged snapshots. Three fresh processes per split use eleven interleaved
rounds. Its declared resident-call objective weights the nonempty phase 10000
and the empty phase 1. Build/startup are recorded separately and excluded from
the speedup numbers; no build-cost amortization or broad application gain is
established. This is a two-candidate selection control after default semantic
discovery, not unrestricted full-recipe measured selection.

The initial extent cohort has nonempty median speedups 1.22x in training and
1.29x on holdout. Training does not clear the unchanged 10% extrema guard, so
the final choice remains baseline; empty holdout medians regress about 7%.
After observing that cohort, one exploratory control doubles both dimensions
and uses fresh seeds. Its nonempty speedups are 1.44x and 1.87x, and both splits
clear the same guard. All four typed input sets are disjoint. The larger control
therefore selects the searched candidate, subject to its declared workload.
Both cohorts, including the rejected one, are retained. This is not a blinded
performance study or evidence that arbitrary Ink applications become faster.

Reproduce from this distribution with its exact independent pins and the local
Cargo entry point on PATH. Output directories must not exist:

```sh
PYTHONPATH=knowledge:planner build/proof-python/bin/python bench/v8-learning/branch-cardinality/measure.py --output build/branch-reproduction
PYTHONPATH=knowledge:planner build/proof-python/bin/python bench/v8-learning/branch-cardinality/measure.py --scale 2 --output build/branch-scaled-reproduction
```

Selected native projects, source, lockfiles, raw reports, exact requests, checked
plans and observation bytes are retained. Absolute paths describe acquisition;
rerunning regenerates relocated paths. Compiled targets and private duplicate
Stores are retired after completed validation. `results.json` binds exact source
revisions and scopes. Frozen-corpus diagnostics are separate from runtime timing.

`replay.py` reproduces both resident-call selection decisions from retained
canonical observation bytes without measuring again. The final CPU suite matches
94 cases across reference/Rust/JavaScript/Rust-Wasm. All 347 planner tests and
five merged knowledge tests pass. The frozen corpus compiles ten programs, admits
24 laws and reuses six, but no alternative passes the measured lifecycle guard.
Its acquisition predates the unrelated closed-traversal authoring merge; focused
merged-package validation is recorded separately. No GPU gain is claimed.
