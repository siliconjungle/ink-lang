# Planning corpus results, 13 October 2026

Ten held-out programs, JavaScript target, installed `balanced` defaults, release
compiler, 2-vCPU Linux sandbox. Each run compiled every program once against a
private copy of the knowledge root. Full tables: [baseline](report-baseline.md)
and [final](report-final.md).

| Run | Change |
|---|---|
| baseline | Distribution as checked out, plus near-miss logging (observations only) |
| structure | + early-exit retargeting fix, structure law library and plan-time instances |
| final | + per-snapshot published-package binding index |

| Measure | baseline | structure | final |
|---|---:|---:|---:|
| Programs selecting an alternative under defaults | 0 / 10 | 0 / 10 | 0 / 10 |
| Programs with an admitted rewrite alternative | 8 | 8 | 8 |
| Semantic proposals admitted (sum) | 52 | 91 | 91 |

| All recipe time, total seconds | 208 | 236 | 202 |

## Findings

1. **Selection, not knowledge, is the binding gate.** Every program's last gate is
   missing comparable measurement evidence. All admitted alternatives are
   discarded, so the defaults' runtime output is unchanged in every run.
2. **The near-miss log found a producer bug on its first run.** The early-exit
   producer emitted a supporting law and instances that `Use` it. Binding a
   definition context for nominal types renamed the supporting law, orphaning
   its instances; this is the "closure" rejection above. `proposals.generate`
   now retargets renamed identities, and early-exit instances are admitted again
   for programs with records (`ast-ancestor`).
3. **Structure laws reach held-out programs.** The absorbing-fold law matched a
   left fold in 7 programs and was admitted in 5 (`compact-set`, `drawing-hit`,
   `index-membership`, `sequence-every`, `spatial-collision`). In the other two
   the accumulator is a record, so no small witness exists. These Boolean cases
   overlap the study's dedicated absorption family, which was authored after its
   corpus was frozen. The structure law is stated without reference to any
   program and also covers products, `||` and other absorbing steps. It was
   chosen knowing the corpus contains Boolean folds, so this is not a pure
   held-out result.
4. **Rejections are premise failures in a few repeated shapes.** These are Bool
   facts the checker could not establish by normalisation, about values bound
   inside callbacks: a key field compared with a free variable (`ast-ancestor`),
   a range test on a record field (`drawing-hit`), or the result of an inner
   `fold_until` (`compact-set`). This suggests missing facts about
   callback-bound items rather than missing laws. It is a hypothesis to test,
   not a measured conclusion.
5. **Planning time is set by the wall clock.** Eight of ten programs stop on the
   60-second budget. Removing 34 seconds of recipe work across the corpus left
   the funnel unchanged, so shorter recipes alone do not deliver more alternatives.

## Reproduce

```sh
PYTHONPATH=planner:knowledge python3 -m ink_planner.corpus \
  --manifest bench/planning-corpus/corpus.json --compiler target/release/ink \
  --knowledge-root knowledge --planning-effort balanced -o build/planning-corpus
```
